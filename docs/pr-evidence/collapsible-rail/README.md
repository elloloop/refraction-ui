# Collapsible Rail review captures

Docs-site pages in light and dark, rendered by the Next.js dev server with Chromium (reduced motion, so the captures do not catch a transition). `before-*` is the App Shell page at the parent revision: until now the library's only collapsible side navigation, which works only inside App Shell's full-page layout. `after-*` is the new Collapsible Rail page at 1440px and 375px; `after-collapsed-*` is the same page after both edge controls were pressed; `after-overlay-open-*` is the 375px viewport with the first demo's overlay opened from its "Open navigation" button. App Shell is unchanged.

`browser-proof.json` records, for every capture, page overflow and browser errors, and on the Collapsible Rail page what the browser measured on the first demo. At 1440px: the rail is 208px wide (13rem) and 56px (3.5rem) collapsed; the edge control is reached with Tab, draws its focus ring, is a 24px target, collapses on Enter, renames itself and keeps focus; the width is stored, survives a reload, and Space expands it again. At 375px: the closed overlay is inert and wholly off screen; opening it moves focus into the rail and places it at the start edge; Escape closes it and returns focus to the opener; with `dir="rtl"` the closed overlay sits off the right edge and opens against it; and none of this writes the stored wide-screen width.

The browser errors in dark mode are a hydration mismatch in the docs site's own colour-mode toggle (one per page load; the proof reloads the page, hence two or three), present on the parent revision too. The parent revision's App Shell page also logs a hydration mismatch of its sidebar id in both modes. The Collapsible Rail page logs nothing in light mode.
